# autohome-parser

Парсер каталога [autohome.com.cn](https://www.autohome.com.cn) → JSON с ценами MSRP
для калькулятора импорта на **abappcn.ru**.

Собирает марки, модели и комплектации автомобилей **не старше 3 лет** (настраивается)
с официальной ценой производителя (厂商指导价) в юанях.

---

## Зачем

Чтобы не вбивать MSRP в калькулятор вручную: калькулятор подгружает готовый JSON
и подставляет цену по выбору «марка → модель → комплектация».

---

## Как работает

Четыре уровня обхода, всё на обычных HTTP-запросах (без headless-браузера):

| Шаг | Источник | Что берём | Кодировка |
|---|---|---|---|
| 1 | `AsLeftMenu/As_LeftListNew.ashx` | все марки + ID | GB2312 |
| 2 | `price/brand-{id}.html` | модели марки, латинское имя марки | GB2312 |
| 3 | `config/series/{id}.html` | даты выхода (параметр `id=8453`) | UTF-8 |
| 4 | `price/series-{id}.html` | названия комплектаций + цены | GB2312 |

### Ключевые особенности реализации

**Экономия запросов.** Шаг 3 (дата) выполняется первым и стоит один запрос.
Если ни одна комплектация модели не проходит фильтр по возрасту — шаг 4 не
выполняется вообще. Большинство старых моделей отсеивается за один запрос.

**Обфускация.** На config-странице часть текста подменена спанами
`<span class='hs_kw*_configCj'></span>` (защита от скрапинга через CSS/шрифты).
Поэтому:
- дата выхода берётся по **числовому** `id=8453`, а не по названию параметра
  (названия обфусцированы);
- цены и названия комплектаций берутся с `price/series-*.html`, где текст чистый.

**Почему не берём цену с config-страницы.** У части комплектаций там стоит
«暂无报价» (цены пока нет), из-за чего столбец цены определяется ненадёжно и
парсер может подхватить соседний числовой параметр (например, мощность в кВт).
На `price`-странице цены чистые и однозначные.

**Разная кодировка.** `price/*` и `AsLeftMenu` отдают GB2312, `config/*` — UTF-8.
Кодировка задаётся явно для каждого типа страницы.

**Внутренний API недоступен.** `car.api.autohome.com.cn` резолвится в приватный
диапазон и отдаёт 403 — используются только публичные страницы.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
# полный обход, авто не старше 3 лет, лимит 5 часов
python main.py --years 3 --time-budget 300

# тест на нескольких марках (15=BMW, 456=Zeekr, 609=AITO)
python main.py --brands 15,456,609 --time-budget 10

# начать обход заново
python main.py --reset
```

### Параметры

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--years` | `3` | максимальный возраст авто в годах |
| `--time-budget` | `300` | лимит времени в минутах |
| `--brands` | — | только указанные `brand_id` через запятую |
| `--min-specs` | `0` | пропускать марки с числом комплектаций меньше N |
| `--delay-min` / `--delay-max` | `1.2` / `2.6` | задержка между запросами, сек |
| `--reset` | — | сбросить состояние обхода |

### Инкрементальность

Прогресс обхода хранится в `state.json`. При достижении `--time-budget` скрипт
сохраняет состояние и выходит; следующий запуск продолжает с места остановки.
Это нужно, чтобы уложиться в лимиты GitHub Actions — полный обход занимает
несколько часов (~200 марок + несколько тысяч моделей).

`state.json` в `.gitignore` — в GitHub Actions он переносится между запусками
через `actions/cache`.

## Результат

```
data/
├── index.json                 # марки → модели + диапазоны цен (лёгкий)
├── specs/{series_id}.json     # комплектации модели (по требованию)
└── autohome_prices.json       # полный дамп (отладка)
```

Двухуровневая структура нужна потому, что полный каталог весит несколько МБ —
грузить его при каждом открытии калькулятора нельзя. Калькулятор загружает
`index.json` сразу, а файл комплектаций — только когда пользователь выбрал модель.

## Автоматизация

`.github/workflows/parse.yml` запускает парсер по расписанию (еженедельно,
`0 2 * * 1`) и коммитит обновлённые данные в `data/`.

Ручной запуск: вкладка **Actions → Parse autohome catalog → Run workflow**
(можно задать `years` и сброс состояния).

> GitHub Actions требует активного коммита для инициализации расписания cron.

## Ограничения и поддержка

- **Названия на китайском.** Латинское имя есть только у марок (из `<title>`
  страницы марки) и только у части — у китайских брендов вроде 极氪 его нет.
  Названия моделей и комплектаций остаются на китайском.
- **Антибот.** При частых запросах возможны 403/503 — реализованы ретраи с
  прогрессивной паузой, ротация User-Agent и задержки. Не стоит уменьшать
  `--delay-min` в продакшене.
- **Хрупкость к изменениям сайта.** Разметка и обфускация autohome меняются;
  при поломке проверять в первую очередь: `RE_BRAND`, `RE_SERIES`,
  `PARAM_ID_LAUNCH_DATE`, регулярку цены в `fetch_specs_with_prices`.
